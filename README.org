#+TITLE: Gigabyte Monitor control

* Introduction

A CLI tool to change monitor settings over USB to the Gigabyte M32U

* Supported monitors
- Gigabyte M32U
- Gigabyte M32Q
- Gigabyte M32QC
- Gigabyte M28UC
- Gigabyte M27Q


In theory any Gigabyte Monitor that uses a Realtek HID device (presumably the
M28U also uses this) to control it over OSD sidekick *should* have the same
protocol, but this is the only one I own.

* To install:

hidapi is bundled with the Go HID library, so no separate install is needed.
On Linux you need the libudev headers (~apt install libudev-dev~ on Debians).

#+begin_src sh
go install github.com/kelvie/gbmonctl@latest
#+end_src

* To use:

#+begin_example
~ ~/go/bin/gbmonctl
ERROR: -get, -prop or -propNum is required

Usage of gbmonctl:
  -get string
        Property to read (a name from the list above, or a raw VCP code like 0x60).
        Prints only the current value. Use "all" for a table of every property
  -n    Dry run: test commands and print instead
  -prop string
        Property to set. Available properties:
                brightness (0-100)
                contrast (0-100)
                sharpness (0-10)
                low-blue-light (0-10)
                        Blue light reduction. 0 means no reduction.
                input-source (0-255)
                        Standard DDC/CI input select (VCP 0x60), e.g. 0x0f DP1, 0x11 HDMI1, 0x12 HDMI2, 0x1b USB-C
                kvm-switch (0-1)
                        Switch KVM to device 0 or 1
                colour-mode (0-3)
                        0 is cool, 1 is normal, 2 is warm, 3 is user-defined.
                rgb-red (0-100)
                        Red value -- only works if colour-mode is set to 3
                rgb-green (0-100)
                        Green value -- only works if colour-mode is set to 3
                rgb-blue (0-100)
                        Blue value -- only works if colour-mode is set to 3
  -propNum uint
        Property number to set instead of -prop
  -val int
        Value to set property to (default -1)

#+end_example

Examples:
#+begin_src sh
# Set brightness to 50
gbmonctl -prop brightness -val 50

# Set contrast to 50
gbmonctl -prop contrast -val 50

# Set sharpness to 5
gbmonctl -prop sharpness -val 5

# Set colour temperature to 2700K for nighttime
gbmonctl -prop colour-mode -val 3
gbmonctl -prop rgb-red -val 100
gbmonctl -prop rgb-green -val 66
gbmonctl -prop rgb-blue -val 35
#+end_src

When using propNum, I don't recommend using values that are out of the ranges
listed, and this program doesn't check, so I'm not liable for monitor damage
that occurs from this.

** Reading values

~-get~ prints only the current value, so it can be used in scripts:

#+begin_src sh
gbmonctl -get brightness     # => 28
gbmonctl -get 0x60           # raw VCP codes work too
gbmonctl -get all            # table of every property and its maximum
#+end_src

Some properties (~count~, ~timer-set~) can be set but not read; ~-get~ exits
with an error for those.

** Switching between two computers

If ~-prop kvm-switch~ switches away but not back, toggle the video input
instead. Read ~-get input-source~ on each computer to find its value, then:

#+begin_src sh
v=$(gbmonctl -get input-source) && if [ "$v" = "17" ]; then n=15; else n=17; fi && gbmonctl -prop input-source -val "$n"
#+end_src

The monitor's USB hub (which includes the control device) follows the KVM, so
the command can only be run from the computer the KVM currently points at --
or connect both of the monitor's USB upstream ports to the same computer.

* Other notes
~fwupd~ seems to delete the hidraw device that this uses, so you will have to
disable fwupd and re-plug in your monitor (hit the KVM switch on the side), see
https://github.com/kelvie/gbmonctl/issues/1
